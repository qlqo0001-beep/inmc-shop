# inmc-shop

서버의 상점. ExcellentShop 5.1.6 의 세 모듈을 한 플러그인에 다시 만들었다 —
**서버 상점**(관리자가 차린 GUI 상점, 가격 5종 · 재고 · 한도 · 회전) · **상자 상점**(플레이어 상점, 가상 창고) ·
**경매장**(화면에서 올리기 · 묶어 보기 · 경고와 벌칙). 모든 설정은 게임 안 화면에서, 값은 Paper Dialog 입력창으로.

사용법은 `GUIDE.md`. 여기는 설계와 안전장치.

## 다른 플러그인과의 경계

| 무엇 | 길 |
|---|---|
| 돈 | core `Currencies` — 상품·상점·모듈마다 화폐. inmc-economy 가 꽂는다(없으면 Vault 가 기본 화폐 하나) |
| 아이템 | core `StoredItem`/`ItemResolver`/`ItemMatcher` — 바닐라 · 모델 번호(스냅샷) · 커스텀아이템(`inmc:…`) · MMOItems |
| 저장 | core `SqlWorker` — 로컬 SQLite, `network.url` 을 적으면 공용 MySQL/MariaDB (화폐와 같은 방식) |
| 입력 | core `DialogForm` — 채팅 입력 없음 |
| 신호 | core `InmcSignalEvent` — `shop/buy` · `shop/sell` · `shop/auction-list` · `shop/auction-buy`(업적이 "상점에서 N번 판매" 를 만든다) |
| PlaceholderAPI | `hook/PapiHook` 한 곳만 PAPI 클래스를 만진다(`ContractTest`) — 명령어 상품의 `%…%` 도 이 훅이 꽂은 함수로 |
| 땅 | 가짜 `BlockPlaceEvent` 로 건축 권한(어느 보호 플러그인이든) + Lands 는 리플렉션(`hook/LandsHook`) |

필수 의존은 `inmc-core` 하나. 나머지는 전부 `load: OMIT`.

## 돈·아이템을 잃거나 복사하지 않게

1. **돈을 먼저 받고 준다.** 가방 공간은 돈을 받기 **전에** 본다(가득 찬 가방 허용이면 발밑에 떨어뜨림). 주다 실패하면 돌려준다.
2. **상자 상점은 빼는 쪽이 먼저다.** 손님이 사면 창고를 먼저 줄이고 주고, 팔면 가방에서 먼저 빼고 창고를 늘린다. 주인의 넣기·회수도 같다.
   창고가 바뀌면 **그 자리에서** DB 쓰기 스레드로 넘긴다(주기 저장이 아니다).
3. **경매 구매는 DB 에서 먼저 잡는다** — `… WHERE state = ACTIVE AND expires > now` 조건부 갱신이 1줄을 바꿔야 성공 → 돈 → 아이템.
   돈이 실패하면 잡은 것을 푼다. 두 서버가 같은 물건을 팔지 않는다.
4. **재고는 공용 DB 에서 원자적으로 뺀다**(`WHERE units >= ?`). 메모리 값만 보고 팔면 서버 수만큼 초과 판매된다.
5. **경매 등록 수수료는 올리기 전에** 받고, 올리기가 실패하면 수수료와 물건을 돌려준다.
6. **한 거래는 한 번만.** core `MenuListener` 의 첫 전달 검사에 더해 사람마다 거래 잠금(`BusyLock`, 10초 만료).
7. **화면이 물건을 들고 있지 않는다.** 경매 올리기 화면은 고른 물건을 가방에 둔 채 칸 번호만 기억하고, 올리는 순간 그 칸을 다시 보고 뺀다.
   값 입력창은 화면을 닫았다 다시 열고 그 사이 접속이 끊길 수도 있어, 화면이 들고 있으면 "닫힐 때 돌려주기" 와 "입력 이어가기" 가 부딪힌다.
   검증기가 이 왕복을 진짜 클릭으로 재현한다.
8. **못 준 것은 버리지 않는다.** 가방이 차서 못 받은 물건(상품 내리기·상점 지우기·임대 끝)은 `shop_return` 에 적고 `/상자상점 돌려받기` 로.

## 여러 서버

- 공용 DB 에 두는 것: 가격 상태 · 전체 재고 · 플레이어 한도 · 회전 상태 · 시장 거래 기록/시세 · 상자 상점 은행 · 경매 · 경고/벌칙.
- **상자 상점(위치·상품·가상 창고)은 로컬 SQLite 에만** — 자리에 묶여 있다. 공용 DB 를 적어도 서버마다 따로.
- 수량은 **차이(delta)로** 더한다. 재고 차감·경매 구매는 조건부 한 줄 갱신, 회전·변동 가격 굴림·시장 주기 계산은 **CAS** — 먼저 바꾼 서버 하나만.
- 다른 서버의 변경은 `network.sync-seconds` 마다 읽어 온다. 공용 DB 가 없으면 메모리가 진실이고 DB 는 비동기로 적는다.

## 가격 5종

| 방식 | 식 |
|---|---|
| 고정 | 적은 값 그대로 |
| **시장 가격** | 아래 |
| 변동 | 최소~최대에서 무작위. 간격(초) 또는 요일×시각마다 다시 굴림. 판매가 ≤ 구매가 |
| 수요 | 시작가 × (1 + 오프셋%). 1개 거래마다 구매/판매 %씩, 최소/최대 %, N초 거래 없으면 M%씩 원래 값으로(원본 바이트코드와 같은 식) |
| 접속자 | 접속자 1명당 % 가감, 최소/최대 |

### 시장 가격 — 거래가 가격을 정하고, 가격이 다시 거래를 움직인다

상품마다 구매·판매 각각 **기본가 · 최저가 · 최고가**. 가격 = 기본가 × 시장 배수 `m` × (1 + 흔들림), 최저~최고로 자르고 정수.
`m` 은 **주기마다 한 번**(기본 30분) 계산한다. 공용 DB 면 한 서버만(주기 칸 CAS).

```
주기의 거래 기록(상품·주기·사람별 산 개수/판 개수) — 한 사람은 주기당 user-cap 개까지만 센다(고래 제한)
p = (B − S) / (B + S + k) × min(1, 참여자 / reference-users)      거래가 적거나 사람이 적으면 약하다
단기 EMA · 장기 EMA → P = short-weight·단기 + (1 − short-weight)·장기
한산 보정 d: 활동량 EMA 가 low-activity 아래면 주기마다 dormancy-step 씩(상한 dormancy-max), 돌아오면 dormancy-decay 배로 풀림
Δ = P·sensitivity·(상품 민감도) + d  →  ±max-step 으로 자름
m ← m(1 + Δ) + (1 − m)·reversion  →  min-multiplier ~ max-multiplier
흔들림 σ = base-noise + (d/dormancy-max)·dormancy-noise + |P|·pressure-noise ,  균등(−σ, σ)
```

많이 사면 오르고 많이 팔면 내린다. 아무도 안 파는 것은 값이 오르고 흔들림이 커져 "지금 팔면 돈이 된다" 가 된다.
구매가와 판매가는 **같은 `m`** 으로 움직이고 판매가는 구매가를 넘지 않는다. 성질은 `MarketTest` 가 시뮬레이션으로 못박는다
(고래 한 명 · 참여자 수 · 최대 변동폭 · 최저가에서 멈춤 · 한산하면 오름 · 돌아오면 가라앉음 · 흔들림 범위).

## 상품 아이템의 저장 방식(동적/스냅샷)

아이템 등록 시스템(인벤키퍼·낚시)과 같은 core `StorageMode`.
**동적**은 원본 정의에서 매번 다시 만든다 — 커스텀아이템을 고치면 상점 아이콘과 산 물건이 같이 바뀐다.
**스냅샷**은 등록한 순간의 모습을 준다 — 원본이 바뀌거나 사라져도 그대로.
고를 수 있는 것은 원본 정의가 따로 있는 아이템(커스텀아이템·MMOItems)뿐이다(`virtual/ItemStorage`). 평범한 바닐라는 두 방식이 같고,
이름·설명을 손으로 붙인 아이템은 참조가 없어 항상 스냅샷이다. 되팔기는 두 방식 모두 **같은 아이템이면** 받는다(정체로 비교).
**상자 상점에는 없다** — 주인이 맡긴 실물을 파는 것이라, 동적으로 다시 만들면 옛 판 물건이 새 정의로 바뀌어 나간다.

## 경매장 — 불쾌하지 않은 보기

- 화면을 열 때의 목록을 **고정**한다. 누가 사 간 칸은 "판매 완료" 로 남아 칸이 밀리지 않는다. "새로고침" 을 눌러야 바뀐다.
- **같은 물건은 한 칸** — 가장 싼 것과 등록 수. 누르면 그 물건의 등록들이 개당 가격 순. 묶는 열쇠는 아이템 바이트의 SHA-1(개수 제외).
- 분류는 왼쪽 탭, 정렬·화폐 필터·이름 검색은 아래 줄 — 사람마다 기억하고, 구매 뒤 같은 페이지로 돌아온다.
- 내 물건은 "(내 물건)" 이고 구매 확인 창이 "내 경매(내리기)" 로 안내한다. 돈이 모자라면 확인 창에서 미리 알린다.
- 관리자 내리기: 그냥 / 경고와 함께(사유). 물건은 판매자의 만료함으로. 경고 N회면 D일 등록 금지, 경고는 E일 뒤 사라짐.
- 정리(`purge-days`)는 **끝난 기록만** 지운다(돈 받음·돌려받음). 받지 않은 물건·돈은 지우지 않는다.

## 원본(ExcellentShop)과 다른 점

- 홀로그램은 PacketEvents 대신 Paper Display 엔티티(저장 안 함). 판매 창의 패킷 가격 미리보기는 설명 줄로.
- 메뉴 설정 파일 대신 게임 안 레이아웃 편집기. 소수점 가격 없음(core `Currency` 가 `Long`).
- 상자 상점은 가상 창고만(상자 속 재고 방식 없음), 상자는 간판이라 안 열리고 안 부서진다(삭제는 관리 화면에서).
- 경매 올리기는 화면에서만(명령어 없음). 금지 월드 대신 허용 월드. 땅 연동은 Lands 하나(+ 모든 보호 플러그인의 건축 권한).
- 옛 ExcellentShop 데이터는 옮기지 않는다(옛 DB 는 비어 있었다).

## 알려진 한계

- 상자 상점 검색은 커스텀 이름·영어 재질 이름·손에 든 것으로 한다(바닐라 한국어 이름은 서버가 모른다).
- 선언하지 않은 `group.<이름>` 권한은 Bukkit 이 OP 에게 준다 — OP 는 판매 배수·상자 상점 한도에서 가장 큰 등급 값을 받는다.
- 두 사람이 필요한 흐름(남의 상자 상점에서 사고팔기, 남의 경매 사기)은 검증기가 건너뛴다 — 게임 안에서 확인.
